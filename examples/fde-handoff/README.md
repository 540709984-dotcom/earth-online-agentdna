# FDE 行业简报交接：虚构演练

**这是合成测试材料，不是真实客户项目、论文结果或多代理实测记录。** “示例制造企业甲”、所有角色和状态事件均为虚构。文件中的 30% 是刻意设置的无依据数字，用来演示拦截。

任务：为示例制造企业甲拟一页 FDE 行业简报，说明需求确认、知识检索、人工复核和小范围试点，所有效果数字必须有可核查的来源与口径。

文件顺序：

1. `task-spec.json`：目标与验收要求。
2. `draft.md`：含一条不应通过的效率承诺。
3. `evidence-ledger.json`：明确缺少效果证据。
4. `handoff-receipt.json`：演示“收到”与“验证失败/尚未验收”可以同时存在。
5. `verification-report.json`：合成失败样例，不代表真实独立复核曾发生。

预期处理：指出“30%”没有样本、基线、统计口径和原始数据，退回删除该承诺或补足证据。修订为 0.1.1 时，0.1.0 的验证不能直接沿用，旧记录应标 `stale`，新版本重新复核。用户未确认实际用途前，`accepted` 继续为 `pending`。

正确输出可以写：“可进行一个需求检索与人工复核的限范围试点；效果待测。”不能把这个建议改写成“已提高效率 30%”。

重新运行时将真实结果写到新的输出目录，并记录实际执行模式；不要改写这些 fixture 后称其为现场证据。无需联网、账号或真实客户资料即可理解此示例。若要声称平台已部署或工作提效，必须另有真实运行与对照数据。
