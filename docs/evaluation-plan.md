# AgentDNA 评估计划 v0.1

## 要回答的问题

- 任务契约本身是否改善单代理的交付？
- 独立复核是否减少关键错误逃逸，代价是多少？
- 多角色协作在哪些任务结构上产生净收益？
- 一个经过批准的规则能否跨执行者、跨任务复用？

## 对照设计

| 组别 | 配置 | 用途 |
|---|---|---|
| A | 单代理 + 同样输入与工具 | 简单可靠基线 |
| B | 单代理 + AgentDNA TaskPacket | 契约本身的效果 |
| C | 研究、构建、独立复核三职责 | 有限协作的净效果 |
| D | 可选：不同模型族的三职责协作 | 检查同源错误的影响 |

各组使用相同任务版本、可访问材料、工具权限、预算上限和停止规则。随机化运行顺序；失败、超时与人工接管都必须留在分母内。

## 任务集

首轮可选20—30项低风险真实工作，覆盖：有来源研究摘要、结构化资料清洗、可运行的本地代码修复。涉及客户、生产、付款、发布或删除的动作只产出草案或使用安全沙箱。

每项任务先定义金标准或至少定义可复核条件：允许来源、关键事实、输出格式、可接受的不确定性、完成者与接收者。

## 指标

| 指标 | 计算 |
|---|---|
| 一次验收通过率 | 无返工 accepted 任务 / 全部任务 |
| 事实错误密度 | 人工金标准判定错误主张 / 100项可核事实 |
| 证据覆盖率 | 有直接来源的关键主张 / 全部关键主张 |
| 交接损失率 | 上游已发现但终稿遗漏或变坏的问题 / 上游已发现问题 |
| 单位验收成本 | 模型、工具与人工成本 / accepted 产物数 |
| 端到端时间 | 从 `active` 到 `accepted` 的墙钟时间 |
| 人工净投入 | 人为操作、复核、返工的分钟数 |
| 严重故障 | 未授权外发、错误删除、秘密暴露、生产误操作次数 |

不要把多个指标合并成没有解释的“总分”。速度、成本和质量分别报告，并保留失败任务例子。

## 分析和停止规则

记录模型版本、工具版本、价格版本、重试次数、提示与权限。尽量让人工验收者不知道组别。报告均值之外，还报告中位数、范围、失败样本和不确定性。

连续两次重试没有减少阻断问题、达到预算/时间上限、评价者彼此冲突、或出现未授权外部动作风险时停止自动运行并转交人。规则更新先在保留集验证，不能只在产生它的任务上自证。

## 小样本解释

小样本只适合寻找任务结构和故障类型，不能宣称“极低错误”。在独立同分布的粗略假设下，零失败的95%上界约为 `3/n`：30例约10%，300例约1%。共享模型、资料或评价器会引入相关错误，实际保障可能更弱。
