# 一人定方向，多 BOT 像基因表达系统一样协作

我正在把自己的 Grok Bot 协作方法开源成 **Earth Online · AgentDNA**。

它借用了 DNA → mRNA → 功能产物的工程逻辑：稳定规则像 DNA，当前任务包像 mRNA，不同 Bot 负责研究、构建与校对，最终产物必须带着来源、版本和验收状态交回。人的判断始终处在系统最上层，决定目标、外部动作和哪些经验值得进入下一版规则。

这套架构解决的不是“多叫几个 Bot 一起说话”，而是五个更具体的问题：

- 目标经过多次交接后仍然对得上；
- 事实能回到原始来源，推论与建议不会混成结论；
- 每份产物绑定任务版本，修改后旧核验自动失效；
- 作者不能自批，接收、核验与业务验收分别记录；
- 有效经验先成为变更提案，经人批准后才进入下一版协作规则。

首个开源版本包含五支可独立使用的 Skill：

| Skill | 作用 |
|---|---|
| `agentdna-research` | 从任务包到证据、综合报告、独立核验的完整研究闭环 |
| `gene-spec` | 冻结目标、权限、预算、责任与停止条件 |
| `evidence-transcribe` | 把资料转成带来源、日期、口径与反证的证据账本 |
| `proofread-gate` | 核对指定版本，分开记录收到、验证与接受 |
| `heritage-proposal` | 把可复用经验写成待人审核的规则变更提案 |

我选择“DNA”作为隐喻，是因为可靠协作靠的不是更多声音，而是稳定规则、有限表达、校对机制和受控传递。它不修改模型权重，也不承诺“Bot 越多越准确”；真实收益需要和单 Bot 基线做同任务、同预算的对照实验。

仓库同时公开深度研究报告、WorkBuddy 部署方法、Grok Bot 角色编制、机器可读模板和一个合成演练。欢迎用真实任务验证，也欢迎把失败案例带回来——只有经得住反证的协作规则，才值得被“遗传”。

**项目口号：** 让每次协作携带证据，让每次交接保留责任，让每次进化经过人的判断。
